# Временная утилита исследования MDV v2

Один адрес, 4800 8N1, без MQTT, служб и установки. Использует существующие
`SerialPort`, сборщик 32-байтных кадров, контрольные суммы и планировщик интервала
MDVWB. Формирование D0/C3 и вывод полей v2 находятся только в `probe.cpp`.
Утилита не входит в основной релиз и не означает готовую поддержку MDV v2.

## Сборка через WSL

Из корня репозитория `/mnt/c/Projects/MDVWB`:

```sh
cmake -S tools/mdv-v2-probe -B out/build/v2-probe -DCMAKE_BUILD_TYPE=Debug
cmake --build out/build/v2-probe -j2
ctest --test-dir out/build/v2-probe --output-on-failure
```

Linux-тест использует псевдотерминал: проверяет реальные байты запросов,
все восемь команд скорости, неполные/чужие/повреждённые ответы, отсутствие
повторной записи при потере C3-ответа и запрет C3 без исходного D0.

ARM64 для контроллера (нужен `aarch64-linux-gnu-g++`):

```sh
cmake -S tools/mdv-v2-probe -B out/build/v2-probe-arm64 \
  -DCMAKE_SYSTEM_NAME=Linux -DCMAKE_SYSTEM_PROCESSOR=aarch64 \
  -DCMAKE_CXX_COMPILER=aarch64-linux-gnu-g++ \
  -DCMAKE_BUILD_TYPE=Release -DPROBE_STATIC=ON -DBUILD_TESTING=OFF
cmake --build out/build/v2-probe-arm64 -j2
```

Результат: `out/build/v2-probe-arm64/mdv-v2-probe`. Статическая сборка не
требует библиотек компилятора или Mosquitto на WB. Запуск на целевом контроллере
проверяется отдельно. Скопировать файл можно через SCP и выполнить `chmod +x mdv-v2-probe`.

## Тест на контроллере

Остановите драйвер, использующий выбранный порт, например `systemctl stop mdvwb@1`.
Если порт занят `wb-mqtt-serial` или другой программой, освободите именно этот
порт. Утилита сама службы не останавливает и не запускает.

Ниже порт и адрес **примерные**: укажите свои. Адрес десятичный `27` = `0x1B`.

Чтение десяти D0-ответов:

```sh
./mdv-v2-probe --port /dev/ttyRS485-1 --address 27 --log v2.log
```

Одна запись скорости 1, затем десять опросов:

```sh
./mdv-v2-probe --port /dev/ttyRS485-1 --address 27 \
  --power on --mode cool --temp 21 --speed 1 --log v2.log
```

Повторяйте с `--speed 2`, `3`, `4`, `5`, `6`, `7`, `auto`, сохраняя остальные
параметры одинаковыми. Каждая команда пишет C3 ровно один раз. По умолчанию
опросы идут с интервалом не меньше секунды; для длительного наблюдения добавьте
`--count 60`. Исходный D0 записывается до C3. Без корректного ответа на него
запись запрещена. Потеря ответа C3 не вызывает повторной записи: следуют D0-опросы.

`--power`, `--mode`, `--temp` и `--speed` обязательны вместе для записи: C3
меняет весь набор. Программа не подставляет настройки из неизвестных полей.
Режимы: `cool`, `heat`, `dry`, `fan`; скорость: `1..7`, `auto`.
Температура `17..30` — ограничение тестовой утилиты, не установленный диапазон
всех устройств v2. Для офисного трёхскоростного устройства используйте скорости
`1`, `4`, `7` как Low/Medium/High. Выключение `--power off` отправляет байт
Power/Mode `00`; сохранение битов режима при выключении здесь не исследуется.

Таймаут по умолчанию 400 мс после завершения отправки. Меняется через
`--timeout-ms`; он должен быть меньше `--period-ms` (по умолчанию 1000 мс).
Это исследовательские значения, а не новые настройки основного драйвера.

В журнал дописываются UTC-время, TX, все полученные порции RX_RAW, выделенные
кадры RX_FRAME с проверкой суммы/команды/адреса, а также известные поля D0.
`speed_raw` выводится без расшифровки: отображение семи скоростей пока неизвестно.
Сохранённые C3-настройки и D0-состояние не приравниваются друг к другу.
Для анализа нужен **весь `v2.log`**, включая исходное состояние и неудачные ответы.

Ctrl+C останавливает тест. Исходный полный D0 сохраняется в журнале,
но настройки автоматически **не восстанавливаются**: кодировка исходной
семискоростной скорости неизвестна. Последняя отправленная уставка остаётся
на устройстве. Нужные конечные настройки задаются отдельной явной командой.

Код завершения: 0 — все запрошенные D0 получены; 2 — отсутствуют ответы;
1 — ошибка параметров/файла/порта; 130 — прерывание. Код 0 не подтверждает
обороты вентилятора или применение скорости, он характеризует только чтение.
