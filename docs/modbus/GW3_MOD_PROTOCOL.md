# MDV GW3-MOD

Профиль: `profiles/modbus/gw3_mod.json`, имя в редакторе **MDV GW3-MOD**.
Источник: предоставленное «Руководство по установке и эксплуатации GW3-MOD»,
таблицы раздела 2 Mapping Tables и предупреждения на печатной странице 33.
Реализация требует проверки на реальном шлюзе: автоматические тесты не
подтверждают совместимость конкретного внутреннего блока.

## Подключение и адреса

- Modbus RTU, **9600 8N1**, **Slave ID 1**.
- WB подключается к Modbus-клеммам **A1/B1/E** шлюза, не к XYE.
- В редакторе шины выбрать порт `/dev/ttyMOD2` для данной установки.
  Порт хранится в конфигурации шины, а не в профиле.
- Адрес в MDVWB равен адресу внутреннего блока **n = 0..63**.
  Все запросы идут Slave 1. Адрес блока 0 не является Modbus broadcast.
- Поиск проверяет индивидуальный Online каждого блока, а не просто ответ шлюза.

## Чтение фактического состояния

В JSON записаны нулевые PDU-адреса. Человеческие обозначения `10001`,
`30001`, `40001` не передаются буквально по проводу.

| Значение | Функция | PDU-адрес | Преобразование |
|---|---|---|---|
| Питание | FC02 | `8*n` | 0 выключен, 1 включён |
| Связь блока | FC02 | `2 + 8*n` | 1 присутствует |
| Режим | FC04 | `32*n` | 1 вентиляция, 2 охлаждение, 3 обогрев, 4 принудительное охлаждение, 6 осушение; бит 7 Auto |
| Скорость | FC04 | `1 + 32*n` | 1..7; бит 7 Auto |
| Уставка | FC04 | `2 + 32*n` | raw / 10 °C |
| Комнатная температура | FC04 | `5 + 32*n` | int16 raw / 10 °C |
| Код аварии | FC04 | `6 + 32*n` | числовой код |

В интерфейсе остаются три скорости: фактические 1–2 отображаются как низкая,
3–4 как средняя, 5–7 как высокая; Auto отдельно. Нулевые режим/скорость
считаются недоступными, а не выдуманными значениями.

Читаемая температура не ограничивается диапазоном команд: внешняя уставка
15 °C будет показана как 15 °C. Знак комнатной температуры и значения при
отключённом/неподдерживаемом датчике нужно проверить на оборудовании.

FC03 поддерживается шлюзом, но возможность использовать `400xx` как источник
фактических значений пока не проверена. Профиль намеренно читает документированные
`300xx` через FC04. Ответ на запись не подменяет фактическое состояние.

## Команды

| Управление | PDU-адрес | Значение записи |
|---|---|---|
| Питание/режим | `1 + 25*n` | Off `0x9F`, On `0xDF`; Fan `0x41`, Cool `0x42`, Heat `0x43`, Dry `0x46`, Auto `0xC0` |
| Скорость | `2 + 25*n` | Low 1, Medium 4, High 7, Auto `0x80` |
| Уставка | `3 + 25*n` | целые **16..32 °C**, шаг 1 |

Выбор режима по протоколу одновременно включает блок. Power On без нового
режима использует команду включения с сохранённым режимом устройства.
Power Off, пришедший после Mode, отменяет ещё ожидающую команду режима.

Руководство предупреждает, что некоторые блоки требуют одновременной записи
всех семи основных параметров. Поэтому используется **FC16 (0x10)**,
семь Holding Registers начиная с `1 + 25*n`: режим, скорость, уставка,
температуры охлаждения/обогрева Auto, горизонтальные/вертикальные жалюзи.

Перед записью проверяется Online и читаются девять Input Registers состояния.
Неизменяемые параметры берутся из этого снимка; ожидающие команды объединяются
в одну запись. Промежуточная скорость 2, например, не округляется до 1.
Половина градуса при сохранении соседней уставки кодируется битом 7:
23,5 °C -> `0x97`; пользовательские команды остаются целыми.
При изменении температуры/скорости отдельно проверяется фактическое питание,
чтобы сохранённый режим не включил выключенный блок.

**Ограничение безопасной записи:** если шлюз возвращает неизвестное значение
соседнего параметра (например, 0 для неподдерживаемых жалюзи или скорости),
команда не отправляется. Причина и смещение поля записываются в журнал.
Значения-заглушки не используются: руководство не гарантирует их безопасность.
Такое поведение, включая включение из выключенного состояния, проверяется
первым на оборудовании. При отказе нужен снимок регистров и журнал, а не
подстановка произвольных значений.

## Задержка подтверждения

Руководство допускает обновление состояния только после завершения внутреннего
цикла шлюза: в приведённом максимальном стенде это около пяти минут.
Для этого профиля `confirmationTimeoutMs = 330000` (330 секунд).

После принятой записи драйвер продолжает обычный опрос и не повторяет команду
только из-за старых значений шлюза. Подтверждение появляется после совпадения
фактического чтения с командой. Веб и планировщик учитывают профильный срок.
Старые профили без этого параметра сохраняют прежнюю схему подтверждения.
Реальная задержка конкретной установки может быть значительно меньше.

## Проверка на контроллере

1. Обновить приложение целиком: одного нового JSON для старого runtime недостаточно.
2. Создать Modbus-шину с профилем MDV GW3-MOD, портом `/dev/ttyMOD2`, 9600 8N1.
3. Выполнить поиск. Для данной установки ожидаются блоки 0..12. Результат
   поиска не применяется автоматически, шина после поиска остаётся остановленной.
4. Добавить один известный блок, сохранить конфигурацию и запустить шину.
5. Сравнить питание, режим, скорость, обе температуры и аварию со штатным шлюзом.
6. По одной проверить Power, Mode, скорости 1/4/7/Auto и уставку 16..32.
   Дождаться фактического обновления перед следующим независимым тестом.
7. Проверить изменение температуры/скорости при выключенном блоке, а также
   сохранение жалюзи, Auto-температур, внешней половинной уставки и скорости 2.
8. При проблеме сохранить журнал `journalctl -u mdvwb@<номер-шины>.service`.

До этих проверок профиль не считается подтверждённым на оборудовании.
